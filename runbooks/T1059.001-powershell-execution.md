# Runbook: Suspicious PowerShell In-Memory Script Block Execution — T1059.001

## Alert Summary
This alert triggers when PowerShell Script Block Logging (Event ID 4104) logs code containing download cradles (`Net.WebClient`, `DownloadString`), in-memory reflection, or dynamic execution primitives (`IEX`, `Invoke-Expression`). Grounded in the Red Canary Threat Detection Report where PowerShell remains the most abused execution technique across enterprise environments.

## Immediate Triage Steps
1. **Analyze Full Script Block Text**: Extract the full decompiled code in `ScriptBlockText`. Check for obfuscated strings, base64 blobs, or URL endpoints.
2. **Identify Target URL / IP**: Extract remote C2 server URLs or staging IPs referenced in the download cradle.
3. **Verify Execution Outcome**: Review subsequent PowerShell error logs (Event ID 4103 / 4104) to confirm whether the payload successfully staged in memory.
4. **Inspect User Context**: Check `User` and `Computer` fields. Determine if the account is an administrative service account or standard end-user.
5. **Cross-Check Process Lineage**: Review parent process of `powershell.exe` (e.g., spawned by `wscript.exe`, `word.exe`, or `explorer.exe`).

## Investigation Queries
```kql
// Pivot on PowerShell scriptblock events and network connections from the host
DeviceNetworkEvents
| where Timestamp between (datetime({AlertTime}) - 5m .. datetime({AlertTime}) + 30m)
| where DeviceName == "{DeviceName}"
| where InitiatingProcessFileName in~ ("powershell.exe", "pwsh.exe")
| project Timestamp, DeviceName, RemoteIP, RemotePort, RemoteUrl, InitiatingProcessCommandLine
```

## Escalation Criteria
Escalate to **Tier 2 / Incident Response** if:
- The script block downloads and executes secondary payloads from unknown remote infrastructure.
- Script invokes credential dumping APIs, LSASS memory handles, or AMSI bypass functions.
- The host establishes persistent outbound beaconing connections.

## Known False Positives
- Software management frameworks (Chocolatey, Scoop, AWS CLI, Azure CLI) downloading packages via PowerShell.
- Systems administration scripts using `Invoke-WebRequest` to pull sanctioned enterprise configuration manifests.
