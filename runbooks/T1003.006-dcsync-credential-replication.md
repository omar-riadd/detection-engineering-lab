# Runbook: Active Directory DCSync Credential Replication Request — T1003.006

## Alert Summary
This alert triggers when Windows Security Event ID 4662 (`An operation was performed on an object`) detects directory service access requests for Directory Replication Service (DRS) extended rights (`DS-Replication-Get-Changes`, `DS-Replication-Get-Changes-All`, or `DS-Replication-Get-Changes-In-Filtered-Set`) originating from a user account or non-domain controller machine. Attackers exploit these extended rights via DCSync (e.g., Mimikatz, Impacket secretsdump) to impersonate a domain controller and simulate directory replication, exfiltrating the entire Active Directory NTDS database or specific high-value account hashes (such as `krbtgt` or Domain Admins) over the network without executing code on the DC.

## Immediate Triage Steps
1. **Identify the Requesting Account**: Check `SubjectUserName` and `SubjectDomainName`. Verify if the account is an authorized Domain Controller machine account (`DC01$`, etc.) or legitimate sync service account (e.g., Azure AD Connect / Entra ID Sync `MSOL_*`). If it is a standard user or administrative user account, treat as an active P1 breach.
2. **Identify Source Host**: Check network logon sessions (Event ID 4624 Type 3) occurring on the Domain Controller immediately preceding or during the Event ID 4662 timestamp to determine the source IP address and client workstation.
3. **Analyze Requested Object and GUIDs**:
   - `1131f6aa-9c07-11d1-f79f-00c04fc2dcd2` (DS-Replication-Get-Changes)
   - `1131f6ad-9c07-11d1-f79f-00c04fc2dcd2` (DS-Replication-Get-Changes-All)
   - `89e4b325-9444-11d1-ae62-00c04fc2dcd2` (DS-Replication-Get-Changes-In-Filtered-Set)
4. **Inspect Source Workstation Telemetry**: Pivot to the source host telemetry (Sysmon EID 1, EID 3, PowerShell EID 4104) to discover the executing process (e.g., `mimikatz.exe`, `python.exe`, `secretsdump.py`, or injected processes).
5. **Enforce Immediate Containment**: Isolate the source workstation from the network immediately and disable or reset the compromised requesting user credentials.

## Investigation Queries
```kql
// Identify unauthorized DRS replication requests on Domain Controllers
SecurityEvent
| where EventID == 4662
| where ObjectServer == "DS"
| where Properties has_any (
    "1131f6aa-9c07-11d1-f79f-00c04fc2dcd2",
    "1131f6ad-9c07-11d1-f79f-00c04fc2dcd2",
    "89e4b325-9444-11d1-ae62-00c04fc2dcd2"
  )
| where not(Account endswith "$")
| where not(Account startswith "MSOL_" or Account contains "AzureADConnect")
| project TimeGenerated, Computer, Account, ObjectName, Properties, AccessMask
```

## Escalation Criteria
Escalate immediately to **Tier 2 / Incident Response (P1/Critical)** if:
- The replication request originated from a standard user account or delegated admin workstation rather than an authorized Domain Controller.
- The source IP is an unmanaged, non-DC host or VPN endpoint.
- Subsequent Kerberos ticket creation (Event ID 4768/4769) using `krbtgt` (Golden Ticket) is observed.

## Known False Positives
- Authorized Microsoft Entra Connect (Azure AD Connect) directory synchronization service accounts.
- Legitimate forest replication activities during new Domain Controller deployment or directory migration.
