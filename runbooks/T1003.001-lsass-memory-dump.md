# Runbook: Suspicious Process Access Request Targeting LSASS Memory — T1003.001

## Alert Summary
This alert triggers when Sysmon Event ID 10 (`ProcessAccess`) detects an unauthorized process requesting handle access with memory-reading permissions (`0x1010`, `0x1F0FFF`) targeting `lsass.exe`. LSASS contains active logon sessions, NTLM password hashes, Kerberos tickets (TGTs), and cached credentials. Access of this type represents an active credential theft attempt (e.g., Mimikatz, ProcDump, Nanodump).

## Immediate Triage Steps
1. **Identify Source Executable**: Examine `SourceImage`, `SourceProcessId`, and `User`. Determine whether the binary is an authorized system management tool or an unapproved executable.
2. **Review Call Trace**: Examine the DLL stack trace in `CallTrace`. Look for standard mini-dumping functions (`dbghelp.dll`, `dbgcore.dll`, `MiniDumpWriteDump`).
3. **Verify Granted Access Mask**: Confirm if access rights include `PROCESS_VM_READ` (`0x0010`) or `PROCESS_ALL_ACCESS` (`0x1F0FFF`).
4. **Check for Dropped Memory Dumps**: Query file creation events on the host within 5 minutes of handle acquisition for dump files (`.dmp`, `.tmp`, or randomized names in `C:\Users\Public\`, `C:\Windows\Temp\`).
5. **Evaluate Network Isolation**: Due to immediate risk of domain credential compromise, initiate host isolation pending credential rotation.

## Investigation Queries
```kql
// Identify processes requesting handle to LSASS and subsequent file creations
DeviceProcessEvents
| where Timestamp between (datetime({AlertTime}) - 5m .. datetime({AlertTime}) + 15m)
| where DeviceName == "{DeviceName}"
| where ProcessCommandLine has_any ("lsass", "procdump", "mimikatz", "comsvcs", "sekurlsa")
| project Timestamp, DeviceName, FileName, ProcessCommandLine, AccountName
```

## Escalation Criteria
Escalate immediately to **Tier 2 / Incident Response (P1/Critical)** if:
- Source process is an untrusted binary or living-off-the-land utility (`comsvcs.dll`, `procdump.exe`, `rundll32.exe`).
- A dump file was created in temporary or user directories.
- Any subsequent lateral movement or DCSync activity is identified from the user account.

## Known False Positives
- Legitimate security agents (EDR, antivirus) performing credential guard checks.
- System administrators taking an authorized crash dump for kernel troubleshooting.
