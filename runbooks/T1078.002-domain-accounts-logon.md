# Runbook: Anomalous Remote Network Logon with Privileged Domain Account — T1078.002

## Alert Summary
This alert triggers when Windows Security Event ID 4624 (`An account was successfully logged on`, LogonType 3) detects remote network authentication using a high-privilege domain account (`corpadmin`, `Administrator`) originating from an unexpected workstation IP. Threat actors exploit valid credentials acquired via credential harvesting, password spraying, or initial access brokers to navigate the network with administrative authorization while evading malware detection signatures.

## Immediate Triage Steps
1. **Identify Source Workstation**: Check `WorkstationName` and `IpAddress` in Event ID 4624. Determine whether the source host is an authorized administrative jump server or an unmanaged client/VPN IP.
2. **Review Authentication Protocol**: Check `AuthenticationPackageName` (Kerberos vs. NTLM). NTLM authentication across internal servers often indicates legacy credential relaying (e.g., Responder, Impacket).
3. **Correlate User Logon Activity**: Cross-reference user activity in the preceding 2 hours across Active Directory. Does the user have multiple concurrent interactive logons from geographically disparate or unauthorized subnets?
4. **Inspect Target Host Telemetry**: Pivot to the target system's process creation log (Sysmon EID 1) around the logon timestamp to identify follow-on remote service execution or command shell spawning.
5. **Enforce Containment**: If unauthorized access is confirmed, disable or reset the account in Active Directory and revoke active Kerberos TGTs.

## Investigation Queries
```kql
// Identify anomalous LogonType 3 network authentications by privileged domain accounts
SecurityEvent
| where EventID == 4624
| where LogonType == 3
| where Account in~ ("corpadmin", "Administrator")
| where not(IpAddress in ("127.0.0.1", "::1", "-"))
| project TimeGenerated, Computer, Account, IpAddress, WorkstationName, AuthenticationPackageName
```

## Escalation Criteria
Escalate immediately to **Tier 2 / Incident Response (P2/High or P1/Critical)** if:
- Remote logon originated from an external, unknown, or non-corporate IP address.
- Follow-on discovery commands (`whoami`, `net`, `nltest`) or file share access occur within 5 minutes of logon.
- The authenticating user confirms they did not initiate the connection.

## Known False Positives
- Enterprise vulnerability scanning tools (Nessus, Qualys) performing authenticated compliance scans.
- Scheduled automation scripts or backup agents connecting to servers using administrative service accounts.
