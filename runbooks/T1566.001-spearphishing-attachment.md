# Runbook: Suspicious File Drop in User Downloads or Staging Directory — T1566.001

## Alert Summary
This alert triggers when an executable or script file (`.vbs`, `.js`, `.hta`, `.lnk`, `.iso`, `.ps1`, `.exe`) is dropped in a user download or staging directory (`\Downloads\`, `\AppData\Local\Temp\`) by an email client, web browser, or archive utility. Grounded in CISA Advisory AA21-116A, this behavior signifies the post-delivery phase of a spearphishing intrusion before user execution.

## Immediate Triage Steps
1. **Analyze Process Lineage**: Identify the writing process (`Image`) and confirm whether it was spawned by Outlook, Thunderbird, Edge, Chrome, or an archive utility (7-Zip, WinRAR).
2. **Inspect Dropped File**: Note the exact path in `TargetFilename`, creation timestamp, and file extension. Check if the file is still present on disk.
3. **Verify Zone Identifier / MOTW**: Check if an accompanying Mark-of-the-Web stream (`TargetFilename:Zone.Identifier`) exists indicating download from the Internet.
4. **Identify Email / Originating URL**: Pivot to secure email gateway (SEG) logs or proxy logs matching the recipient and timestamp to identify sender address, subject line, or referral URL.
5. **Check for Execution**: Query process creation events within 5 minutes of file creation to verify if the dropped file was executed.

## Investigation Queries
```kql
// Identify process execution following the file drop on the affected host
DeviceProcessEvents
| where Timestamp between (datetime({AlertTime}) - 5m .. datetime({AlertTime}) + 15m)
| where DeviceName == "{DeviceName}"
| where InitiatingProcessFileName in~ ("explorer.exe", "wscript.exe", "cscript.exe", "mshta.exe", "powershell.exe")
| project Timestamp, DeviceName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine
```

## Escalation Criteria
Escalate to **Tier 2 / Incident Response** if:
- Process creation logs confirm execution of the dropped script/binary.
- Network connections to external unclassified IP addresses or dynamic DNS domains occur from the executing host.
- Multiple users across the organization received or downloaded identical file names within the same time window.

## Known False Positives
- Legitimate software installers downloaded intentionally by developer or engineering staff.
- Approved enterprise management agents staging update scripts in temporary directories.
