# Runbook: Password Brute Force or Credential Stuffing — T1110.001

## Alert Summary
This alert triggers when stateful correlation detects 5 or more failed authentication attempts (Event ID 4625) targeting the same user account within a 60-second sliding time window. Adversaries conduct automated password guessing, dictionary attacks, or credential stuffing to compromise local or domain user credentials.

## Immediate Triage Steps
1. **Identify Target Account and Source IP**: Extract `TargetUserName`, `IpAddress`, `WorkstationName`, and `ComputerName` from the failed logon events. Determine whether the source IP is an internal workstation, a VPN gateway, or an external IP.
2. **Determine Failure Reason (SubStatus)**: Review the logon failure substatus codes:
   - `0xC000006A`: Bad password (indicates brute force or credential spray).
   - `0xC0000064`: User name does not exist (indicates username enumeration or wide credential stuffing).
   - `0xC0000234`: Account locked out (indicates automated tool tripped lockout threshold).
3. **Check for Subsequent Successful Logon**: Immediately query for a successful authentication event (Event ID 4624) for the same `TargetUserName` from the same source IP within 30 minutes following the failed attempts. A successful logon after repeated failures indicates a successful compromise.
4. **Inspect Source Host Telemetry**: If the source IP originates internally, inspect the source endpoint for compromised services, malware loaders, or credential dumping tools (Mimikatz, Hydra, CrackMapExec).
5. **Containment & Remediation**: If an unauthorized attack is confirmed:
   - Temporarily disable or reset the credentials of the targeted account.
   - Block the attacking IP address on the network perimeter or host firewall.
   - Terminate any active sessions established by the account.

## Investigation Queries
```kql
// Identify brute force failed logon attempts followed by potential success
let TargetUser = "{TargetUserName}";
let TimeWindow = 30m;
SecurityEvent
| where TimeGenerated between (datetime({AlertTime}) - TimeWindow .. datetime({AlertTime}) + TimeWindow)
| where EventID in (4625, 4624)
| project TimeGenerated, EventID, TargetUserName, IpAddress, WorkstationName, SubStatus, Activity
| order by TimeGenerated asc
```

## Escalation Criteria
Escalate immediately to **Tier 2 / Incident Response (P1/Critical)** if:
- Multiple failed logons are immediately followed by a successful logon (Event ID 4624).
- The targeted account is a Domain Admin, Enterprise Admin, or sensitive service account.
- The attack originates from an internal workstation, indicating an active lateral movement phase.

## Known False Positives
- Misconfigured services, scheduled tasks, or mobile devices with cached expired passwords attempting repeated reconnections.
