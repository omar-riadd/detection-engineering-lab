# Runbook: Active Directory Domain Account Reconnaissance via Net CLI — T1087.002

## Alert Summary
This alert triggers when Sysmon Event ID 1 (`ProcessCreate`) or Security Event ID 4688 detects execution of `net.exe` or `net1.exe` with command-line flags targeting Active Directory domain objects (e.g., `net user /domain`, `net group "Domain Admins" /domain`, `net accounts /domain`). Threat actors routinely use built-in Windows administrative utilities during initial post-exploitation discovery to map privileged users, password lockout policies, and domain group memberships without introducing uncompiled third-party tools.

## Immediate Triage Steps
1. **Identify Executing User & Host**: Check `User`, `Computer`, and `ProcessId`. Is this command executed from a standard end-user workstation by a non-administrative account?
2. **Review Parent Process Tree**: Inspect `ParentImage` and `ParentCommandLine`. 
   - Malicious indicators: Spawning from `powershell.exe`, `cmd.exe` running from `C:\Users\Public\`, `wscript.exe`, `cscript.exe`, or office applications (`winword.exe`, `excel.exe`).
   - Benign indicators: Scheduled management script running from an authorized management path or provisioning service.
3. **Check for Discovery Command Clusters**: Look for rapid sequences of associated discovery commands within a 15-minute window:
   - `nltest /domain_trusts` (T1482)
   - `whoami /groups` / `whoami /all` (T1033)
   - `net group "Domain Controllers" /domain`
   - `ipconfig /all`, `systeminfo`, `netstat -ano`
4. **Determine User Role & Justification**: Contact the user or system owner to determine whether there was an active, authorized administrative task or IT troubleshooting session.

## Investigation Queries
```kql
// Identify command line execution of net/net1 domain recon commands
DeviceProcessEvents
| where Timestamp between (datetime({AlertTime}) - 15m .. datetime({AlertTime}) + 15m)
| where DeviceName == "{DeviceName}"
| where FileName in~ ("net.exe", "net1.exe")
| where ProcessCommandLine has "/domain" and ProcessCommandLine has_any ("user", "group", "accounts")
| project Timestamp, DeviceName, AccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, FileName, ProcessCommandLine
```

## Escalation Criteria
Escalate to **Tier 2 / Incident Response (P3/Medium or P2/High)** if:
- Reconnaissance command was spawned by an unexpected parent process (e.g., Office application, suspicious PowerShell script, web server worker process).
- Multiple discovery commands (`net`, `nltest`, `whoami`, `quser`) were executed in rapid succession by a non-IT account.
- The activity is accompanied by network connections to external or non-standard IP addresses.

## Known False Positives
- IT helpdesk technicians troubleshooting user account lockouts or group memberships.
- Standard corporate logon scripts that verify user domain group membership upon workstation sign-in.
