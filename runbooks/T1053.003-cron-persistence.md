# Runbook: Persistence via Scheduled Cron Job Modification — T1053.003

## Alert Summary
This alert triggers when processes modify system cron tab directories (`/etc/cron.d/`, `/etc/cron.daily/`, `/etc/cron.hourly/`, `/var/spool/cron/crontabs/`, `/etc/crontab`) or invoke `crontab -e`. Threat actors abuse cron jobs on Linux systems to establish reliable persistence or execute scheduled callbacks with root privileges.

## Immediate Triage Steps
1. **Identify Modified Cron Entry**: Inspect the targeted cron configuration file or spool entry to review the scheduled command line, script path, and execution frequency.
2. **Inspect Referencing Script/Binary**: Locate and hash any payload or binary invoked by the cron entry (e.g. scripts residing in `/tmp`, `/dev/shm`, `/var/tmp`).
3. **Verify Process Lineage & User**: Check which user and parent process modified the cron job (e.g., interactive bash shell vs package installer).
4. **Audit Cron Service Logs**: Review `/var/log/cron` or `journalctl -u cron` to see if the scheduled job has already executed.
5. **Neutralize Unauthorized Job**: Remove the unauthorized crontab line or cron.d file and kill any executing spawned child processes.

## Investigation Queries
```kql
// Pivot on Linux cron modifications and scheduled task telemetry
DeviceProcessEvents
| where Timestamp between (datetime({AlertTime}) - 30m .. datetime({AlertTime}) + 30m)
| where DeviceName == "{DeviceName}"
| where ProcessCommandLine has_any ("/etc/cron", "/var/spool/cron", "crontab")
| project Timestamp, DeviceName, AccountName, InitiatingProcessFileName, FileName, ProcessCommandLine
```

## Escalation Criteria
Escalate to **Tier 2 / Incident Response** if:
- Cron entry points to payloads in temporary directories (`/tmp`, `/var/tmp`, `/dev/shm`).
- Cron entry initiates network communication, reverse shells, or downloads from remote hosts.
- The modification occurred during off-hours or originated from a compromised non-admin account following privilege escalation.

## Known False Positives
- Standard system utility package installations or updates (e.g. `logrotate`, `anacron`, `certbot`).
- Authorized DevOps automation scripts (Ansible, Puppet, Chef, SaltStack) updating scheduled jobs.
