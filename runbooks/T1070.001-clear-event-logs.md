# Runbook: Clear Windows Event Logs via Wevtutil or PowerShell — T1070.001

## Alert Summary
This alert triggers when `wevtutil.exe` is executed with the `cl` (clear-log) switch or PowerShell invokes log-clearing cmdlets (`Clear-EventLog`, `Limit-EventLog`, `EventLogSession.ClearLog`). Adversaries routinely purge Windows event logs (Security, System, Application, PowerShell, Sysmon) immediately prior to deploying ransomware, executing lateral movement, or completing exfiltration to destroy forensic evidence and blind security operations centers.

## Immediate Triage Steps
1. **Identify Executing Process and Account**: Determine `Image`, `ProcessCommandLine`, `User`, and parent process tree. Check if the executing account is a standard user, local administrator, or domain admin.
2. **Determine Target Event Log**: Check command line arguments for the specific channel cleared (e.g., `wevtutil cl Security`, `wevtutil cl System`, `wevtutil cl "Microsoft-Windows-Sysmon/Operational"`). Clearing the Security or Sysmon logs is almost always malicious.
3. **Inspect Surrounding Host Telemetry**: Review process activity on the endpoint within -30 minutes to +10 minutes of the log clear command for suspicious tools (e.g., vssadmin, certutil, mimikatz, ransomware droppers).
4. **Inspect Correlated Remote Log Ingestion**: In an enterprise environment, check if centralized SIEM / Wazuh log shipping retained events before local log destruction occurred.
5. **Initiate Host Containment**: If the log clear command was not part of an approved IT change window, isolate the host immediately to preserve memory and disk artifacts for digital forensics.

## Investigation Queries
```kql
// Identify process tree executing wevtutil or PowerShell log clearing
DeviceProcessEvents
| where Timestamp between (datetime({AlertTime}) - 30m .. datetime({AlertTime}) + 10m)
| where DeviceName == "{DeviceName}"
| where ProcessCommandLine has_any ("wevtutil", "Clear-EventLog", "clear-log", "Limit-EventLog")
| project Timestamp, DeviceName, FileName, ProcessCommandLine, InitiatingProcessFileName, AccountName
```

## Escalation Criteria
Escalate immediately to **Tier 2 / Incident Response (P1/Critical)** if:
- Security, Sysmon, or PowerShell Operational channels were cleared.
- Execution was preceded by credential dumping, lateral movement, or privilege escalation.
- Command was executed by an unauthorized user or interactive remote session (RDP, WinRM, PsExec).

## Known False Positives
- Rare scheduled IT maintenance scripts clearing non-critical application logs during automated testing or base-image provisioning.
