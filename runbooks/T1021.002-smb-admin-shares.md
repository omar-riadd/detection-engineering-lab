# Runbook: Lateral Movement via Administrative SMB Network Share Access — T1021.002

## Alert Summary
This alert triggers when Windows Security Event ID 5140 (`A network share object was accessed`) records remote network access targeting administrative shares (`ADMIN$`, `C$`) from a non-machine user account over an external network IP. Threat actors (e.g., APT29, ransomware affiliates) utilize administrative shares to stage remote execution tools, deploy secondary payloads, or execute lateral movement commands using PsExec, SMBexec, or WMI/DCOM wrappers.

## Immediate Triage Steps
1. **Identify Source and Destination Hosts**: Check `IpAddress` (source client) and `Computer` (target destination host) to map the lateral traversal path.
2. **Review User Account Context**: Verify `SubjectUserName` and domain. Is the account an authorized Domain Administrator performing documented maintenance, or a compromised user account demonstrating anomalous privilege escalation?
3. **Inspect Target File Operations**: Query Windows Security Event ID 5145 (`Detailed File Share`) or Sysmon Event ID 11 (`FileCreate`) on the target machine for files written to `C:\Windows\`, `C:\Windows\System32\`, or root shares around the alert time (e.g., `.exe`, `.dll`, `.bat`, `.vbs`, or service binaries).
4. **Correlate with Service Creation**: Query Windows System Event ID 7045 or Windows Security Event ID 4697 on the target machine to detect whether a new service was remotely registered (typical PsExec or SMBexec behavior).
5. **Verify Process Lineage on Source**: Pivot to the source workstation to identify the parent process initiating the SMB connection (e.g., `cmd.exe`, `powershell.exe`, `psexec.exe`, `impacket`).

## Investigation Queries
```kql
// Identify administrative share access across endpoints
SecurityEvent
| where EventID == 5140
| where ShareName endswith @"\ADMIN$" or ShareName endswith @"\C$"
| where not(IpAddress in ("127.0.0.1", "::1", "-"))
| where not(Account endswith "$")
| project TimeGenerated, SourceHost=IpAddress, TargetHost=Computer, Account, ShareName, AccessMask
```

## Escalation Criteria
Escalate immediately to **Tier 2 / Incident Response (P2/High)** if:
- Remote admin share access is followed by service installation (EID 7045 / 4697) or process execution (Sysmon EID 1).
- The accessing account does not normally administer the target system or is a standard workstation user.
- Multiple hosts across the subnet are accessed in rapid succession (worm-like propagation or network-wide ransomware staging).

## Known False Positives
- Enterprise vulnerability scanners (e.g., Tenable Nessus, Qualys, Rapid7) conducting authenticated host scans.
- Centralized deployment tools (SCCM, Tanium, PDQ Deploy, Microsoft Endpoint Configuration Manager) deploying patches.
